# Понятные названия источников площади в итоговой статистике

## Цель

Сделать итоговое сообщение расчёта понятным пользователю Revit: показывать фактическое имя выбранного параметра площади и не выводить внутреннее имя Revit API `HOST_AREA_COMPUTED`.

Изменение относится только к тексту итоговой статистики. Выбор параметров, чтение значений, резервные расчёты, распределение площади по сторонам света и подсчёт элементов не меняются.

## Формат сообщения

Если для окон выбран параметр, выводятся строки:

```text
Окна — параметр «Площадь остекления» (экземпляр): 14
Окна — «Высота» × «Ширина»: 0
```

Если для витражных панелей выбран параметр, выводятся строки:

```text
Витражные панели — параметр «Площадь стекла» (тип): 2
Витражные панели — системный параметр «Площадь»: 0
```

Между блоками окон и панелей сохраняется пустая строка. Если настройка категории выключена, её блок, как и сейчас, не показывается.

Имя и область берутся из уже восстановленного выбранного объекта параметра. GUID в итоговом сообщении не показывается: он нужен для точного внутреннего восстановления, но перегружает пользовательский текст.

## Совместимость и безопасность

Текст `Площадь` для резервного источника панели является пользовательским названием встроенного параметра, из которого текущая логика читает `BuiltInParameter.HOST_AREA_COMPUTED`. Сам вызов Revit API и его поведение остаются неизменными во всех конфигурациях R2019–R2026.

Новые обращения к документу, элементам или параметрам Revit не добавляются. Транзакции и поток расчёта не меняются.

## Проверка

Регрессионный тест должен подтвердить:

- вывод имени и области выбранного параметра окон;
- вывод имени и области выбранного параметра витражных панелей;
- отсутствие `HOST_AREA_COMPUTED` в пользовательском итоговом сообщении;
- сохранение обеих существующих величин статистики и пустой строки между блоками;
- отсутствие изменений в расчётных вызовах окон и витражных панелей.

После изменения выполняются тестовый harness и сборки R2019–R2026.
