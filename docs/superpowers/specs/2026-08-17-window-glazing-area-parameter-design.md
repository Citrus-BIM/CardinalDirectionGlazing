# Площадь окон из выбранного параметра

## Цель

Дать пользователю возможность брать фактическую площадь остекления окон из выбранного параметра семейства вместо существующего расчёта по максимальным значениям высоты и ширины. Настройка применяется только к категории «Окна» и не меняет расчёт витражных панелей, витражных стен и базовых стен-остекления.

## Интерфейс

В основном окне команды появляется GroupBox `Площадь остекления из параметра`. Внутри располагаются одна строка с чекбоксом `Окна` и выпадающим списком параметров.

- При выключенном чекбоксе список недоступен, а площадь всех окон вычисляется существующим способом: высота × ширина.
- При включённом чекбоксе список становится доступен и выбор параметра обязателен.
- В список входят только параметры категории «Окна» со `StorageType.Double` и типом данных «Площадь», найденные в текущем документе и загруженных связанных документах.
- Параметры экземпляра и типа показываются раздельно, например `В_Площадь остекления (экземпляр)` и `В_Площадь остекления (тип)`.
- Если подходящих параметров нет, список остаётся пустым. Команда не запускает расчёт с включённым чекбоксом, пока пользователь не выберет параметр.

Список агрегируется по имени параметра и области действия `экземпляр/тип`, чтобы одинаково работать с общими, проектными и семейными параметрами, а также с параметрами, имеющими разные внутренние идентификаторы в разных документах.

## Настройки

В `CardinalDirectionGlazingSettings.xml` сохраняются:

- признак использования параметра площади для окон;
- имя выбранного параметра;
- область действия параметра: экземпляр или тип;
- GUID общего параметра, если он доступен, как дополнительный устойчивый идентификатор.

При загрузке сначала восстанавливается параметр с тем же именем и областью действия. GUID используется для точного поиска, но при обработке другого документа допускается поиск по имени: это поддерживает одинаково названные параметры с разными идентификаторами. Старые XML-файлы без новых полей десериализуются с выключенным чекбоксом и сохраняют прежнее поведение.

## Расчёт площади

Для каждого обрабатываемого окна вычисляется резервная площадь существующим алгоритмом:

1. Из типа окна читаются `FAMILY_ROUGH_HEIGHT_PARAM`, `FAMILY_ROUGH_WIDTH_PARAM`, `CASEWORK_HEIGHT` и `CASEWORK_WIDTH`.
2. Выбираются максимальная высота и максимальная ширина.
3. Резервная площадь равна их произведению во внутренних единицах Revit.

Если настройка параметра выключена, резервная площадь используется сразу. Если настройка включена, параметр ищется в выбранной области действия окна: на экземпляре или на типе. Сначала выполняется поиск по сохранённому GUID общего параметра, затем — по имени.

Значение выбранного параметра используется только когда параметр найден, имеет `StorageType.Double` и его значение строго больше нуля. Если параметр отсутствует, имеет другой тип хранения, не заполнен или равен нулю, для этого окна автоматически применяется резервная площадь высота × ширина. Отрицательное или нечисловое значение также считается недействительным и приводит к резервному расчёту.

Все значения остаются во внутренних единицах площади Revit, поэтому дополнительное преобразование единиц перед суммированием и записью не требуется.

## Статистика и диагностика

Команда считает только окна, которые действительно были отнесены к помещению или пространству и добавлены в одну из сторон света. Одно и то же окно учитывается в статистике один раз по паре `документ + UniqueId`.

После завершения расчёта при включённой настройке выводится сводка:

- сколько окон рассчитано по выбранному параметру;
- сколько окон рассчитано по высоте × ширине из-за отсутствующего или недействительного значения.

В существующую диагностическую трассировку окна добавляются имя и область выбранного параметра, прочитанное значение, фактически использованный источник площади и причина резервного расчёта. Включение записи JSON этим изменением не производится.

## Совместимость Revit API

Команда остаётся `IExternalCommand` с ручной транзакцией. Чтение параметров не требует транзакции; существующая транзакция записи итоговых площадей в помещения и пространства не меняется.

Проверка типа данных «Площадь» реализуется условной компиляцией: через `Definition.ParameterType` для старых версий API и через `Definition.GetDataType()`/`SpecTypeId.Area` для новых. Решение должно собираться в конфигурациях `R2019`–`R2026` без смешивания Revit API разных лет.

## Регрессионные проверки

Автоматические тесты фиксируют следующие сценарии:

1. Выключенная настройка всегда использует высоту × ширину, даже если передано положительное значение параметра.
2. Включённая настройка использует положительное значение выбранного параметра.
3. Отсутствующий параметр приводит к расчёту по высоте × ширине.
4. Нулевое, отрицательное или нечисловое значение приводит к расчёту по высоте × ширине.
5. Статистика не считает одно окно повторно и раздельно учитывает параметр и резервный расчёт.
6. Старый XML настроек без новых полей сохраняет прежний режим.
7. Новый XML сохраняет и восстанавливает чекбокс, имя, область действия и GUID.
8. XAML содержит GroupBox, чекбокс `Окна` и связанный с ним список параметров.
9. Все существующие регрессионные тесты продолжают проходить.
10. Проект успешно собирается для Revit 2019, 2020, 2021, 2022, 2023, 2024, 2025 и 2026.

## Вне объёма

- отдельные параметры площади для витражных панелей и стен;
- сопоставление разных параметров разным семействам в одном запуске;
- автоматическое изменение или заполнение параметров окон;
- изменение алгоритма определения стороны света и пространственной принадлежности окна.
